1. Accomplished Since Last Meeting: Article Review
- Faye
    - 16. Hidden In Memory: Memory Poisoning
        - focuses on memory poisoning where tampered data has been written into the agent's memory
        - simulates an attack in 3 stages:
            - injection: malicious content
            - retrieval: poisoned memory in the future
            - usage: memory influences agent's response
        - investigates threats and suggests solutions 
        - no testing of a solution
        
    - 21. Progent
        - uses privilege control to deny malicious MCP tool usages 
        - implementation inserts a module between agent and tool
        - highly effective results
    
    - 22. Securing AI Agent with Info-Flow Control   
        - planner orchestrates calls and determines info flows -> assigns labels to data 
        - tracks info from prompt -> response -> planner memory -> LLM content -> tool argument -> actions 

- Rosnita
    - 13. Memory Poisoning Attacks in LLM Agents 
        - various strategies to stop poisoning of memory 
        - includes monitoring and data checks 
    - 14. Threats in LLM-powered AI Agent workflows
        - provides no solutions, only research 
        - threat models + testing 
        - provides suggestions but are not implemented/tested
    - 15. GuardAgent: Safeguard LLM Agents
        - takes an LLM agent as a guardrail to: make an action plan -> generate code
        - tested on healthcare + webagent 
        - can be applied to different things

- Conlyn 
    - 5. AIR: Improving Agent Safety through Incident Response
        - DSL (domain-specific language) -> nested rules for attack 
        - full response for agents
        - prevent + immediate attacks -> generating new rules in own language
        - integrate into agent (during runtime) -> in loop 
            - increases the prompt runtime by a large amount
    - 8. AgentArmor: Securing LLM Agents via Structured Graph Abstraction 
        - data flow, dependency graphs, malicious instructions
        - finds out where malicious instructions come from 
            - places blame for the attack (tool call)
        - used for indirect prompt injection (e.g., a command from a random line in an email)
        - runs at runtime to build the graph 
            - found to be expensive (70% of runtime)
        - doesn't provide information on how the graph is built and in what order
        - constructs graph with each new execution 
    - 23. Shield MCP
        - file storage, MCP servers, etc. 
        - 80 techniques of attack (protects)
        - Risks:
            - between agent runtime -> info of each MCP
            - malicious construction
            - tool changes during calls/compromises
        - Solution:
            - run hash to see what is changed per call validation -> tools -> database
            - custom models to check intent
                - if instruct, then it is denied
                - if inform, it continues
    - 24. Semantic Attacks on Tool-Augmented LLMs
        - results: not as good, high false-positive rate 
        - uses Ollama 3.5
